SaaS Roadmap

Piano Maintainer To-Do

This document tracks the remaining work needed to move the current Django app from a working multi-company product branch to a production-ready SaaS launch.

The core SaaS foundation is now in place: company-owned data, active-company session context, membership-based permissions, invitation acceptance, password recovery, private media delivery, audit activity, CSV/reporting, and tenant-aware scheduled work-order generation. The next phase is about proving the app is launch-safe through production validation, tenant-admin polish, operational policy, and a final cross-tenant safety pass.

SaaS Branch Standards

The SaaS branch should now be treated as a clean multi-tenant product track with its own fresh database. The legacy private-use database does not need to constrain schema or authorization design on this branch.

  1. Make the schema fully SaaS-native. All tenant-owned records should use required company relationships, membership-based permissions should become the primary authorization model, and company settings should remain company-scoped rather than singleton-style.
  2. Remove transitional legacy helpers. Default-company autofill, compatibility fallbacks, and any logic kept only to protect the older single-tenant database should be removed before deployment.
  3. Treat media as private from day one. New uploads should be private by default, company-authorized through Django, and delivered with short-lived signed URLs.
  4. Target a fresh Postgres deployment. This branch should be prepared for a new production database with clean migrations, seed/demo data where helpful, and no requirement to support in-place upgrade from the private legacy database.

Launch Gate Plan

  1. Gate 1: Local SaaS verification. Run a clean-database migration, bootstrap the first company/admin, run the maintenance test suite, and run saas_readiness_report.
  2. Gate 2: Production services validation. Prove Postgres bootstrap, SMTP email delivery, object-storage upload, and signed private media delivery in a production-shaped environment.
  3. Gate 3: Tenant-admin lifecycle polish. Finish self-serve member activation/reactivation messaging, role-change clarity, invitation history, and first-run setup visibility.
  4. Gate 4: Operations policy. Decide platform support access, backup cadence, restore expectations, monitoring, incident ownership, and support escalation rules.
  5. Gate 5: Final SaaS safety pass. Re-check reports, exports, search/filter paths, background jobs, media endpoints, public QR requests, and production cutover posture for cross-company leaks.
  6. Gate 6: Demo and onboarding data. Add a clean seed/import story for demo tenants and new-customer onboarding without relying on the legacy private-use database.
Payments are intentionally excluded from this roadmap, per your direction. The right next milestone is a trustworthy, operationally boring multi-company launch.
